# BACKROW 11.0 — Presenter Mode

Open `http://127.0.0.1:8080/present.html` after starting BACKROW.

Presenter mode is a bilingual stage controller over the real product, not a prerecorded mockup. It has seven scenes:

1. **Physical path** — source → projector → room → audience position.
2. **Exact loss** — `2.5% → 25%` shows meaning changed, not merely style.
3. **Live product** — the same-origin embedded app runs the judge case.
4. **Architecture** — custom AudienceNet, third-party Tesseract, classical CV, deterministic guards.
5. **Fix → rescan** — repair the failing region and prove risk disappears.
6. **Scientific boundary** — explicitly separates verified engineering from human-readability claims that still require real readers.
7. **Close** — returns control to the judge: `CHOOSE A SLIDE`.

## Controls

- `START PRESENTATION`: rehearsal narration + auto-advance.
- `SPACE`: play/pause.
- `←` / `→`: previous/next scene.
- `EN` / `ID`: switch copy and rehearsal narration.

## Voice

For YCWC compliance, the submission build does **not** depend on any external or paid voice/TTS plugin. Presenter mode uses visible captions and the browser/OS built-in Speech Synthesis only for private rehearsal. During exhibition, the participant delivers the explanation live.

## Why the room visualization exists

It is functional, not decorative. The product thesis is about the physical delivery chain. The last-row phone is shown because BACKROW's real two-device workflow measures what the audience-position camera receives rather than only inspecting the source slide.
